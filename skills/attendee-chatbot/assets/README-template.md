## Local smoke test

```
npm install
npm run dev
```

Open the URL Vite prints. Look for the floating chat icon in the bottom-right corner. Try the three test prompts from the skill's Step 8 (document-grounded, out-of-scope, hallucination probe).

## Build for production

```
npm run build
```

Produces `dist/widget.js` and `dist/widget.css`. Upload both to your static hosting (S3, R2, Netlify drop, GitHub Pages — anything HTTPS-served).

## Embed on the event page

Open `embed-snippet.html`, replace the placeholder URLs with your hosted file URLs, and paste the resulting two lines into the `<body>` of the event page (just before `</body>` works fine). Do not add a placeholder `<div>` — the widget mounts itself.

## Updating the bot

Re-invoke the `attendee-chatbot` skill in the same project folder. The skill detects existing state in `agent.json` and offers the right update flow (new PDF, branding tweak, welcome message, etc.).

## Security

- The API key in `src/config.ts` is baked into the production bundle. Only embed `widget.js` on pages gated behind registration.
- For a public-page deployment, ask the skill for the token-mint variant.
- Do not commit `src/config.ts` to a public repo — the API key is in there.

## Troubleshooting

- **"Sorry — I hit an error reaching the assistant."** — open browser devtools → console. Look for the `[event-chatbot] stream error` log. Usually a stale API key or a deleted agent.
- **Bot answers "I don't have that" to a question that IS in the PDFs.** — the PDF may have uploaded but failed to attach. Re-run the skill with "rebuild the agent" and confirm `agent.json` lists all the files.
- **Bot makes things up.** — tighten the system prompt's rules block (re-run the skill, accept the prompt-refresh prompt) or add a clarifying PDF.
- **Two chat icons appear.** — the host page added a placeholder `<div>` for the widget. Remove it; the widget mounts its own root.
